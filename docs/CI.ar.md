# التكامل المستمر وسياسة الفروع

## لماذا

طلبات الدمج ٣ إلى ١١ كانت قاعدة كلٍّ منها الفرع السابق لا `main`. النتيجة أن الأحد عشر
طلباً ظهرت كلها بحالة «مدمج» بينما لم يصل إلى `main` سوى الأوّلين — وبقيت خمس مراحل
كاملة (التقويم الهجري، الإحصائيات، الإعدادات، المواقع العربية، التذكيرات) خارج الإنتاج.
ولم يكن في المستودع ما يبني المشروع قبل الدمج، فمرّ عطل إقلاع استُهلك عليه أربعة طلبات دمج.

الملفان في `.github/workflows` يمنعان تكرار الحالتين.

## `ci.yml` — بوابة الجودة

| الوظيفة       | ما تفعله                                            | متى                           |
| ------------- | --------------------------------------------------- | ----------------------------- |
| `base-branch` | ترفض أي طلب دمج قاعدته ليست `main`                  | على كل طلب دمج                |
| `verify`      | `typecheck` ← `prettier --check` ← `lint` ← `build` | طلبات الدمج والدفع إلى `main` |

الترتيب مقصود: الأسرع أولاً ليفشل السير مبكراً.

## `android.yml` — حزمة قابلة للتجربة

يبني حزمة الويب ويُزامن Capacitor ثم يُخرج APK:

- **بلا أسرار توقيع:** APK تصحيح (`assembleDebug`).
- **مع أسرار التوقيع:** APK إصدار موقَّع + AAB للنشر.

الحزم تُرفع كأثر باسم `manar-android-<sha>` وتبقى ١٤ يوماً.

### الأسرار المطلوبة للتوقيع

تُضاف في `Settings → Secrets and variables → Actions`:

| السر                    | المحتوى                                                               |
| ----------------------- | --------------------------------------------------------------------- |
| `MANAR_KEYSTORE_BASE64` | ملف الـkeystore مُرمَّزاً base64: `base64 -w0 manar-release.keystore` |
| `MANAR_STORE_PASSWORD`  | كلمة مرور المخزن                                                      |
| `MANAR_KEY_ALIAS`       | اسم المفتاح                                                           |
| `MANAR_KEY_PASSWORD`    | كلمة مرور المفتاح                                                     |

المفتاح لا يُكتب في الشجرة إلا داخل خطوة البناء، ويُحذف في خطوة `always()` بعدها.
ولا يُرفع إلى المستودع أبداً: `android/app/build.gradle` يقرأه من
`android/keystore.properties` (مُستثنى من Git) أو من متغيّرات البيئة.

## الإعداد المتبقّي في واجهة GitHub

حماية الفرع `main` (`Settings → Branches → Add rule`):

- `Require a pull request before merging`
- `Require status checks to pass` واختيار `أنواع وتنسيق وبناء` و`قاعدة الدمج main`
- `Require branches to be up to date before merging`

## القاعدة

كل طلب دمج قاعدته `main`. إن احتجت البناء فوق عمل غير مدمج بعد، اعمل على فرع واحد
أطول، أو أدمج السابق في `main` أولاً — لا تُسلسل طلبات الدمج.
